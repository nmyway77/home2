01
A simple truth that designers must embrace in order to create more effective products and experiences is the fact that we are not the user.
🔊
디자이너들이 더 효과적인 제품과 경험을 만들어 내기 위해 받아들여야 하는 단순한 진리는 우리(= 제품을 만드는 디자이너들)가 사용자가 아니라는 사실이다.
📌the user(여기서) (제품을 실제로 쓰게 될) 사용자 — cf. 이용자 일반 · 디자이너(만드는 사람) ↔ 사용자(쓰는 사람)embrace ≒ accept(여기서) (사실을) 기꺼이 받아들이다 — cf. 껴안다truth → true진리, 사실 → (형) 사실인effective → effectiveness효과적인 → (명) 효과 ↔ ineffectivein order to V~하기 위해서 (목적)product / experience제품 / 경험(제품을 쓰며 겪는 체험)the fact that ~~라는 사실 (동격 that)
📐 문장 구조도
✏️ 문법★ 단어의 뜻 the user: we are not the user — 여기서 user는 ‘이용자 일반’이 아니라 디자이너가 만든 제품을 실제로 쓰게 될 사람. 만드는 사람(designers = we) ↔ 쓰는 사람(the user)의 대비가 글 전체의 축이다. / ★ 목적격 관계대명사 that: A simple truth that designers must embrace — embrace의 목적어가 빠진 불완전한 절 → 선행사 truth를 꾸미는 목적격 관계대명사 that. ✗ that designers must embrace it(목적어 중복). / ★ 긴 주어 + 단수 동사 is: 주어 핵심은 A simple truth(단수) → 관계절·to부정사구를 지나 is. ✗ products and experiences are(가까운 명사에 일치 금지). / 동격의 that: the fact that we are not the user — that 뒤가 완전한 절 → the fact의 내용을 밝히는 동격 접속사. ‘우리가 사용자가 아니라는 사실’. / we의 정체: we are not the user — we = 글쓴이를 포함한 디자이너들(일반인 we 아님). 해석에 ‘우리(= 디자이너들)’로 밝힘.
【디자이너가 먼저 받아들여야 할 진실 — 나는 사용자가 아니다】 글 전체의 출발점이 되는 주어진 문장이다. 핵심 단어는 the user(사용자)로, 디자이너인 ‘우리’는 아무리 제품을 잘 알아도 그 제품을 실제로 쓰게 될 사람과는 다르다는 사실을 인정해야 한다는 말이다. embrace는 여기서 ‘껴안다’가 아니라 ‘(불편한 사실을) 기꺼이 받아들이다’라는 뜻이다.
학교 축제 때 우리 반이 방탈출 부스를 만들었다고 해 보자. 문제를 직접 낸 우리 반 친구들은 답을 이미 알고 있으니 단서가 너무 쉬워 보이고, 그래서 일부러 더 어렵게 꼬아 놓는다. 그런데 막상 축제 날 다른 반 학생들이 들어오면 10분이 지나도 첫 번째 자물쇠조차 못 연다. 만든 사람은 아무리 노력해도 ‘처음 보는 사람’의 눈으로 볼 수 없기 때문이다. 앱이나 게임, 학원 숙제 관리 프로그램도 똑같다.
대비: 디자이너는 자기 제품을 가장 잘 아니까 사용자 입장도 안다 ✗ / 디자이너는 사용자가 아니라는 사실을 인정해야 한다 ○
다음 문장은 왜 디자이너가 사용자가 될 수 없는지 그 이유(너무 가깝다)를 설명한다. ★ A truth that designers must embrace ~ is (단수) / the fact that = 동격!
02
We’re much too close to what we build to objectively see it and understand how users will interact with it.
🔊
우리(= 디자이너들)는 우리가 만드는 것에 너무나 가까워서 그것(= 우리가 만드는 것)을 객관적으로 보고 사용자들이 그것(= 우리가 만드는 것)과 어떻게 상호 작용할지 이해할 수 없다.
📌close to ~(여기서) (심리적으로) ~에 너무 가까운, 밀착된 — cf. (공간) 가까운 · (동) 닫다objectively ← objective객관적으로 ← (형) 객관적인 ↔ subjectively 주관적으로interact with → interaction~와 상호 작용하다 → (명) 상호 작용much too + 형용사너무나 ~한 (much가 too를 강조)too ~ to V너무 ~해서 V할 수 없다build(여기서) (제품을) 만들다, 개발하다 — cf. (건물을) 짓다
📐 문장 구조도
✏️ 문법★ 단어의 뜻 close: much too close to what we build — 거리가 가깝다는 말이 아니라 자기가 만든 것에 너무 익숙하고 밀착되어 한발 떨어져 보지 못한다는 뜻. 바로 뒤 objectively(객관적으로)와 대비된다. / ★ too ~ to V = 너무 ~해서 ~할 수 없다: much too close ~ to objectively see — 부정어가 없어도 ‘~할 수 없다’로 해석. ≒ so close ~ that we cannot see. much는 too를 강조(✗ very too). / 관계대명사 what = ~하는 것: to what we build — what = the thing which. 전치사 to의 목적어(명사절). ✗ to that we build. / 동사원형 병렬: to objectively see it and understand — to 하나에 see와 understand가 병렬(to 생략). objectively는 to와 see 사이에 들어간 부사(분리부정사). / 간접의문문 how + S + V: how users will interact with it — understand의 목적어. 의문사 + 주어 + 동사 어순. ✗ how will users interact. 명사절이라 미래 will 사용 가능.
【만든 사람은 너무 가까워서 객관적으로 못 본다】 앞 문장의 ‘우리는 사용자가 아니다’에 대한 이유를 대는 문장이다. 핵심은 too close(너무 가까운)로, 물리적 거리가 아니라 자기가 만든 것에 너무 익숙하고 애착이 있어서 한 발 떨어져 보지 못한다는 뜻이다. objectively(객관적으로)는 내 생각을 빼고 남의 눈으로 본다는 말이다.
수행평가로 쓴 영어 에세이를 생각해 보자. 내가 쓴 글은 몇 번을 다시 읽어도 틀린 곳이 잘 안 보인다. 머릿속에 하고 싶은 말이 이미 들어 있어서 빠진 단어도 눈이 저절로 채워 읽기 때문이다. 그런데 짝꿍에게 보여 주면 ‘여기 문장 무슨 뜻이야?’ 하고 금방 짚어 낸다. 디자이너도 마찬가지로, 자기가 만든 버튼이 어디 있는지 이미 알기 때문에 처음 쓰는 사람이 그 버튼을 못 찾아 헤맬 거라는 것을 상상하기 어렵다.
대비: 만든 사람이 제일 정확하게 평가할 수 있다 ✗ / 만든 사람은 너무 가까워서 객관적으로 보기 어렵다 ○
다음 문장은 그렇다면 좋은 인터페이스는 무엇으로 만들어지는지(실제 사용자 관찰) 답을 제시한다. ★ much too ~ to V = 너무 ~해서 V할 수 없다 / what we build = 우리가 만드는 것!
03
The best user interfaces are those that have been shaped by observations of real users and their interactions with them.
🔊
가장 좋은 사용자 인터페이스는 실제 사용자들과 그들(= 실제 사용자들)의 그것들(= 사용자 인터페이스들)과의 상호 작용에 대한 관찰에 의해 형성되어 온 것들(= 사용자 인터페이스들)이다.
📌user interface사용자 인터페이스(사람이 기기를 쓰도록 만든 화면·버튼·메뉴)shape ≒ form, mold(여기서) (모습을) 형성하다, 다듬다 — cf. (명) 모양observation ← observe관찰 ← (동) 관찰하다 — cf. (다른 뜻) 의견, 소견interaction ← interact상호 작용 ← (동) 상호 작용하다real ↔ imaginary실제의 ↔ 상상의those that ~~하는 것들 (those = 앞의 복수 명사 대신)
📐 문장 구조도
✏️ 문법★ 단어의 뜻 shaped by observations: have been shaped by observations — ‘모양이 잡히다’를 넘어 실제 사용자를 지켜본 결과에 따라 다듬어졌다는 뜻. 앞 문장의 ‘디자이너의 눈(객관적이지 못함)’과 대비되는 해결 방향. / ★ those that + 복수 동사: those that have been shaped — those = the user interfaces(복수) → 주격 관계대명사 that 뒤도 복수 have. ✗ those that has. / 현재완료 수동태: have been shaped by — 인터페이스는 ‘다듬어지는’ 대상 → have been p.p. ‘(지금까지) 형성되어 왔다’. / A and B 병렬 (of의 목적어): observations of real users and their interactions with them — 관찰 대상 두 가지: 사용자 자체 + 사용자가 인터페이스와 상호 작용하는 방식. / 대명사 their / them: their = real users / with them = the user interfaces. 같은 문장에서 가리키는 대상이 다르므로 주의.
【최고의 화면은 실제 사용자를 지켜본 결과】 (C)의 두 번째 문장으로, 앞의 문제(디자이너의 눈으로는 부족하다)에 대한 해결 방향을 보여 준다. 핵심은 shaped by observations(관찰에 의해 다듬어진)으로, 좋은 user interface(사용자 인터페이스 = 사람이 기계를 쓰도록 만든 화면·버튼·메뉴)는 디자이너의 머릿속이 아니라 실제 사용자를 지켜본 결과로 만들어진다는 말이다.
학교 급식 키오스크를 새로 들였다고 해 보자. 처음엔 메뉴 선택 버튼이 화면 구석에 작게 있어서 1학년들이 줄 서서 한참 헤맸다. 영양 선생님이 며칠 동안 학생들이 어디서 손가락을 멈추고 어디를 잘못 누르는지 지켜본 뒤, 버튼을 화면 가운데로 크게 옮겼더니 줄이 금방 줄었다. 이처럼 실제 쓰는 사람이 어떻게 행동하는지 보고 고친 화면이 가장 좋은 화면이 된다.
대비: 좋은 화면은 디자이너의 감각만으로 나온다 ✗ / 좋은 화면은 실제 사용자를 관찰해 다듬어진다 ○
다음 문장은 ‘그렇다면 어떻게?’라는 질문을 던져 구체적인 방법으로 넘어간다. ★ those that have been p.p. (those = 복수 → have) / their ≠ them!

04
So how can designers shape their work to be more effective?
🔊
그렇다면 디자이너들은 어떻게 그들(= 디자이너들)의 작업이 더 효과적이 되도록 다듬을 수 있을까?
📌shape(여기서) (작업을) 다듬다, 만들어 가다 — cf. (명) 모양, 형태so(여기서) 그렇다면, 그러면(앞 내용을 받아 질문을 이끎) — cf. 그래서work(여기서) 작업물, 작품 — cf. 일하다 · 효과가 있다effective ↔ ineffective효과적인 ↔ 효과 없는shape A to be BA를 B가 되도록 다듬다
📐 문장 구조도
✏️ 문법★ 단어의 뜻 shape: how can designers shape their work — 명사 ‘모양’이 아니라 동사 ‘다듬다, (원하는 모습으로) 만들어 가다’. 앞 문장 have been shaped by observations와 같은 동사를 이어 받아 ‘어떻게 다듬을까’를 묻는다. / ★ 5형식 shape + O + to be: shape their work to be more effective — 목적어 their work가 ‘더 효과적이 되도록’. 목적격보어 자리 to부정사. ✗ shape their work being. / 의문사 + 조동사 + 주어 + 동사: how can designers shape — 직접의문문 어순(조동사가 주어 앞). 간접의문문(S02 how users will)과 비교. / 순서 단서 So + 질문: So는 (C) 앞부분(실제 사용자를 관찰해야 한다)을 받아 ‘그렇다면 어떻게?’라고 묻는다 → 바로 뒤에 답 (B) An incredibly effective way가 와야 한다.
【그렇다면 어떻게? — 방법을 묻는 질문】 (C)의 마지막 문장으로, 지금까지의 문제 제기를 정리하고 해결책을 묻는 질문이다. 핵심은 So(그렇다면)와 how(어떻게)로, 앞에서 ‘실제 사용자를 관찰해야 한다’고 했으니 이제 그것을 실제로 어떤 방법으로 하느냐를 묻는다. shape는 여기서 ‘모양’이 아니라 ‘(작업을) 다듬다, 만들어 가다’라는 동사다.
담임 선생님이 학급 회의에서 ‘우리 반 청소가 자꾸 대충 끝나는 문제가 있다’고 말한 뒤 ‘그럼 어떻게 하면 청소를 제대로 할 수 있을까?’ 하고 묻는 장면을 떠올려 보자. 이 질문이 나오면 다음에는 반드시 ‘구역별 담당자를 정하자’ 같은 구체적인 답이 나와야 한다. 질문만 던지고 끝나는 회의는 없다. 글도 마찬가지라서, 물음표로 끝난 이 문장 바로 뒤에는 그 답이 와야 자연스럽다.
대비: 질문 뒤에 또 다른 문제 제기가 이어진다 ✗ / 질문 바로 뒤에 해결 방법이 답으로 나온다 ○
다음 문장 (B)의 ‘한 가지 엄청나게 효과적인 방법’이 바로 이 질문의 답이다(순서 단서). ★ shape + O + to be ~ = O가 ~이 되도록 다듬다 / So how ~? → 답이 이어진다!
05
An incredibly effective way is with usability testing.
🔊
한 가지 엄청나게 효과적인 방법은 사용성 테스트를 활용하는 것이다.
📌usability testing사용성 테스트(실제 사람에게 써 보게 하며 쓰기 편한지 확인하는 방법)usability ← usable ← use사용성, 쓰기 편한 정도 ← (형) 사용할 수 있는incredibly ← incredible엄청나게, 믿을 수 없을 정도로 ← (형) 믿을 수 없는way ≒ method, means(여기서) 방법 — cf. 길be with ~(여기서) ~을 가지고 하는 것이다(수단) — cf. ~와 함께 있다
📐 문장 구조도
✏️ 문법★ 단어의 뜻 usability: usability testing — use(쓰다) + -able(~할 수 있는) + -ity(명사) → ‘얼마나 쉽게 쓸 수 있는가’. 제품 기능 검사가 아니라 사람이 써 보는 모습을 시험하는 것. / ★ 부사 + 형용사 수식: incredibly effective — 형용사 effective를 꾸미는 것은 부사. ✗ incredible effective → ✓ incredibly effective. / be with = 수단의 with: is with usability testing — ‘사용성 테스트를 가지고 (하는 것)이다’. 앞 질문 how can designers ~?(어떻게)에 대해 수단을 답하므로 with. ≒ is to use usability testing. / 순서 단서 An ~ way: ‘한 가지 방법’은 (C) 끝 질문 how can designers ~?에 대한 답 → (B)는 (C) 뒤.
【답은 사용성 테스트】 앞 문장의 질문 ‘어떻게?’에 대한 직접적인 답이다. 핵심은 usability testing(사용성 테스트)으로, usability는 use(사용하다)+able(~할 수 있는)+ity에서 온 말로 ‘얼마나 쓰기 편한가’를 뜻한다. 즉 실제 사람에게 제품을 써 보게 하고 얼마나 쉽게 쓰는지 확인하는 방법이다.
새로 나온 모바일 게임 회사가 정식 출시 전에 고등학생 20명을 불러 게임을 해 보게 한다고 하자. 개발자들은 옆에서 말없이 지켜보며 학생들이 어느 단계에서 설명을 못 읽고 넘어가는지, 어떤 메뉴를 찾지 못해 화면을 이리저리 누르는지 기록한다. 개발자 자신은 수백 번 해 본 게임이라 절대 알 수 없던 불편함이 이 자리에서 드러난다. 이것이 바로 사용성 테스트다.
대비: 디자이너가 스스로 여러 번 써 보면 충분하다 ✗ / 실제 사용자에게 써 보게 하고 관찰하는 것이 효과적이다 ○
다음 문장은 이 방법의 목표가 무엇인지 세 가지로 나누어 자세히 설명한다. ★ incredibly(부사) + effective(형용사) / be with ~ = ~을 가지고 하는 것!

The goal of this method is to uncover problems in a design, discover existing opportunities, and learn more about the behaviors and preferences of users by asking participants to engage in realistic activities.

【사용성 테스트의 세 가지 목표】 (B)의 두 번째 문장으로, 사용성 테스트가 무엇을 얻으려는 방법인지 구체적으로 풀어 준다. 핵심은 uncover problems(문제를 밝혀내다), discover opportunities(개선할 기회를 찾다), learn about preferences(사용자가 좋아하는 것을 알다)의 세 가지이고, 방법은 참가자에게 realistic activities(실제와 같은 활동)를 해 보게 하는 것이다.
학교 도서관이 새 도서 검색 앱을 만들었다고 해 보자. 학생 몇 명에게 ‘수행평가용 진로 관련 책을 찾아서 대출 예약까지 해 봐’라는 실제 같은 과제를 준다. 그러면 예약 버튼이 안 보인다는 문제가 드러나고, 학생들이 ‘친구가 빌린 책 보기’ 기능을 원한다는 새 기회도 발견되며, 학생들이 제목보다 표지 사진을 먼저 본다는 습관도 알게 된다.
대비: 참가자에게 ‘이 앱 어때?’라고 의견만 묻는다 ✗ / 실제 같은 과제를 시켜 보고 행동을 관찰한다 ○

This technique is effective for understanding how well a design will perform once it is in the hands of real users.
🔊
이 기법(= 사용성 테스트)은 디자인이 일단 실제 사용자들의 손에 들어가면 그것(= 그 디자인)이 얼마나 잘 작동할지를 이해하는 데 효과적이다.
📌perform → performance(여기서) (제 기능을) 발휘하다, 작동하다 — cf. 공연하다 · 수행하다 → (명) 성능technique ≒ method기법, 기술in the hands of ~~의 손에 (들어가), ~가 쓰게 되어once ≒ as soon as(접) 일단 ~하면, ~하자마자 — cf. (부) 한 번be effective for -ing~하는 데 효과적이다how well ~얼마나 잘 ~하는지 (정도의 간접의문문)
📐 문장 구조도
✏️ 문법★ 단어의 뜻 perform: how well a design will perform — ‘공연하다’가 아니라 ‘(디자인이) 제 기능을 발휘하다, 잘 작동하다’. how well(얼마나 잘)과 함께 ‘실전 성능’을 묻는다. / ★ 간접의문문 how well + S + V: understanding how well a design will perform — understanding의 목적어(명사절). 어순: how well + 주어 + 동사. ✗ how well will a design perform. / ★ 시간 부사절 once + 현재 시제: once it is in the hands of real users — 미래 상황이라도 시간·조건 부사절은 현재 시제. ✗ once it will be. 【출시 전에 실전 성적을 미리 본다】 (A)의 첫 문장으로, 앞에서 설명한 방법을 This technique(이 기법)로 받아 그 쓸모를 정리한다. 핵심은 perform으로, 여기서는 ‘공연하다’가 아니라 ‘(디자인이) 제 기능을 발휘하다, 잘 작동하다’라는 뜻이다. in the hands of real users는 실제 사용자들이 손에 쥐고 쓰게 되는 순간을 말한다.
시험 전에 모의고사를 보는 이유를 생각해 보자. 교과서를 혼자 읽을 때는 다 안다고 느끼지만, 실제 시험과 똑같은 시간과 형식으로 모의고사를 풀어 보면 어느 단원이 약한지, 시간이 얼마나 모자라는지 정확히 알게 된다. 사용성 테스트도 디자인이 진짜 사용자에게 넘어가기 전에 치르는 모의고사와 같다. 실전에서 얼마나 잘 통할지를 미리 확인하는 것이다.
대비: 디자인의 성능은 출시 후에야 알 수 있다 ✗ / 사용성 테스트로 출시 전에 미리 알 수 있다 ○
마지막 문장은 디자이너가 이 결과를 가지고 무엇을 하는지(수정을 통한 개선)로 글을 마무리한다. ★ how well + S + will V (명사절) / once + 현재 시제 (부사절)!

학원에서 단어 시험 앱을 만든다고 해 보자. 영어를 잘하는 선생님들끼리만 써 보는 게 아니라, 실제로 앱을 쓸 고1·고2 학생 몇 명에게 일주일 동안 써 보게 한다. 학생들이 ‘틀린 단어만 다시 보기 기능이 필요해요’, ‘글씨가 너무 작아요’라고 반응하면 그것을 반영해 1차 수정을 하고, 다시 써 보게 해서 2차 수정을 한다. 이렇게 진짜 사용자를 닮은 사람들의 반응을 바탕으로 여러 번 고칠수록 앱은 점점 좋아진다.
대비: 한 번 만들고 디자이너의 판단으로 끝낸다 ✗ / 대표적인 사용자의 반응을 바탕으로 계속 수정한다 ○

문장 01 · 목적격 관계대명사 that / 긴 주어 + 단수 동사 / 동격 that
A simple truth that designers must embrace in order to create more effective products and experiences is the fact that we are not the user.
디자이너들이 더 효과적인 제품과 경험을 만들어 내기 위해 받아들여야 하는 단순한 진리는 우리가 사용자가 아니라는 사실이다.
Tier 1
주어 truth(단수) + is
A simple truth ~ is — ✗ are(products and experiences에 일치) → ✓ is
Tier 2
목적격 관계대명사 that
embrace의 목적어가 빠진 불완전한 절 → truth 수식. ✗ embrace it
Tier 2
동격 that
the fact that + 완전한 절 = ~라는 사실.
Tier 3
the user / embrace
사용자(만드는 사람 ↔ 쓰는 사람) / (사실을) 받아들이다.
문장 02 · too ~ to V / 관계대명사 what / 간접의문문
We’re much too close to what we build to objectively see it and understand how users will interact with it.
우리는 우리가 만드는 것에 너무나 가까워서 그것을 객관적으로 보고 사용자들이 그것과 어떻게 상호 작용할지 이해할 수 없다.
Tier 1
간접의문문 어순
how users will interact — ✗ how will users interact → ✓ how users will interact
Tier 2
too ~ to V
너무 ~해서 ~할 수 없다. much가 too 강조 ✗ very too
Tier 2
관계대명사 what
what we build = 우리가 만드는 것. ✗ that we build(선행사 없음)
Tier 4
동사원형 병렬
to objectively see it and (to) understand ~.
문장 03 · those that + 복수 동사 / 현재완료 수동
The best user interfaces are those that have been shaped by observations of real users and their interactions with them.
가장 좋은 사용자 인터페이스는 실제 사용자들과 그들의 그것들과의 상호 작용에 대한 관찰에 의해 형성되어 온 것들이다.
Tier 1
those that + 복수
those = user interfaces → have. ✗ has been shaped → ✓ have been shaped
Tier 2
현재완료 수동태
have been p.p. — 인터페이스는 ‘다듬어지는’ 대상.
Tier 3
shape / observation
다듬다·형성하다 / 관찰.
Tier 4
대명사 구별
their = real users / them = user interfaces.
문장 04 · 5형식 shape + O + to be / 직접의문문
So how can designers shape their work to be more effective?
그렇다면 디자이너들은 어떻게 그들의 작업이 더 효과적이 되도록 다듬을 수 있을까?
Tier 2
shape + O + to be
목적격보어 to부정사. ✗ being → ✓ to be
Tier 3
shape = 다듬다(동사)
명사 ‘모양’ 아님. S03 have been shaped를 이어 받음.
Tier 4
순서 단서 So how ~?
질문으로 (C)가 끝남 → 답인 (B)가 뒤에 온다.
문장 05 · 부사 + 형용사 / 수단의 with
An incredibly effective way is with usability testing.
한 가지 엄청나게 효과적인 방법은 사용성 테스트를 활용하는 것이다.
Tier 1
부사가 형용사 수식
incredibly effective — ✗ incredible effective → ✓ incredibly effective
Tier 3
usability testing
사용성 테스트 — 실제 사람이 써 보게 하는 방법.
Tier 4
be with ~ (수단)
‘~을 가지고 (하는 것)이다’ — how 질문에 대한 답.
문장 06 · 보어 to부정사 병렬 / by -ing / ask O to V
The goal of this method is to uncover problems in a design, discover existing opportunities, and learn more about the behaviors and preferences of users by asking participants to engage in realistic activities.
이 방법의 목표는 참가자들에게 현실적인 활동에 참여하도록 요청함으로써 디자인상의 문제를 밝혀내고, 현재 있는 기회를 발견하고, 사용자들의 행동과 선호에 대해 더 많이 알아내는 것이다.
Tier 1
to부정사 3개 병렬
to uncover, discover, and learn — ✗ discovering / learns → ✓ 동사원형
Tier 1
ask + O + to V
asking participants to engage — ✗ engage / engaging → ✓ to engage
Tier 2
주어 goal + is
The goal of this method is (단수).
Tier 3
uncover / preference / participant
밝혀내다 / 선호 / 참가자.
문장 07 · 간접의문문 how well / once + 현재 시제
This technique is effective for understanding how well a design will perform once it is in the hands of real users.
이 기법은 디자인이 일단 실제 사용자들의 손에 들어가면 그것이 얼마나 잘 작동할지를 이해하는 데 효과적이다.
Tier 1
시간 부사절 현재 시제

Tier 1
간접의문문 어순
how well a design will perform — ✗ how well will a design perform
Tier 2
전치사 + 동명사
effective for understanding.
Tier 3
perform = 작동하다
공연하다 ✗. This technique = 사용성 테스트(순서 단서).

Designers can use this method to improve their work through subsequent revisions based on the findings from representative users.
디자이너들은 대표적인 사용자들로부터 얻은 발견 사항에 기반한 후속 수정을 통해 그들의 작업을 개선하기 위해 이 방법을 사용할 수 있다.
